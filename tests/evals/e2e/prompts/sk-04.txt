Add a paginated, filterable, sortable listing API over an in-memory collection of record dicts. Create a new module at src/records_api.py (importable as `records_api`). Pure Python only: no web framework, no HTTP server, no I/O -- this is a query layer over a list passed in by the caller. The public function must be exactly: list_records(records, *, filters=None, sort_by=None, sort_dir='asc', page=1, limit=10). `records` is a list of record dicts; a record has exactly the four fields 'id' (int), 'name' (str), 'category' (str), 'priority' (int), all always present and non-None, e.g. {'id': 1, 'name': 'mango', 'category': 'tools', 'priority': 3}. A canonical sample dataset (use it in your unit tests; the grader passes its own conforming lists directly to the function) is: ids 1..12 with (name, category, priority) = (mango, tools, 3), (apple, toys, 1), (peach, tools, 2), (banana, food, 3), (cherry, toys, 2), (grape, food, 1), (lemon, tools, 1), (fig, food, 2), (olive, toys, 3), (date, tools, 2), (kiwi, food, 1), (plum, toys, 2). Semantics, applied strictly in this order: filter, then sort, then paginate. (1) FILTER: `filters` is None or a dict mapping field name -> required value; a record matches only if every listed field compares equal (==) to its value (multiple entries AND together). None or {} means no filtering. A filter KEY that is not one of the four record fields raises ValueError; a value that merely matches no records is NOT an error and yields an empty result. (2) SORT: `sort_by` is None (preserve the input order of `records`) or one of the four field names; any other value raises ValueError. `sort_dir` must be 'asc' or 'desc' and is validated even when sort_by is None; anything else raises ValueError. Sorting must be STABLE in both directions: records whose sort field compares equal keep their relative order from the input (for 'desc' that means a stable descending sort, not a reversed ascending list). (3) PAGINATE: `page` is 1-based and `limit` is the page size; page < 1 or limit < 1 raises ValueError (so limit=0 is an error). A page past the end of the filtered result is NOT an error: it returns an empty items list with the normal envelope. (4) ENVELOPE: return a dict with exactly these five keys and no others: 'items' (list of the record dicts for the requested page), 'total' (int: number of records after filtering, before pagination), 'page' (int: the requested page, echoed), 'limit' (int: the requested limit, echoed), 'has_next' (bool: True iff page * limit < total). All validation errors are raised as ValueError before any envelope is returned. The function must not mutate the `records` list it is given. Also add unit tests for the new module under tests/.
