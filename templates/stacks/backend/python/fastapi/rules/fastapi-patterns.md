# FastAPI backend patterns

Stack-specific conventions for the backend. This overlay is installed into `.claude/rules/` only
when the **Python · FastAPI** stack is selected. It complements the generic rules — read
`.claude/rules/code-organization.md`, `.claude/rules/design-patterns.md`, and
`.claude/rules/testing.md` first; this file makes them concrete for FastAPI.

## Stack

- **Python 3.11+**, **FastAPI**, async **SQLAlchemy 2.0** (`Mapped` / `mapped_column`) or the
  project's chosen data layer, **Pydantic v2** + **pydantic-settings**.
- Tests: **pytest** + **pytest-asyncio** (`asyncio_mode = "auto"`), **httpx** `ASGITransport`.
- Tooling: **ruff** (lint + format), **mypy**.

Run the project's own commands for these tasks (see the **Commands** section of `CLAUDE.md`):
install, run/dev, test, lint + types, format.

## Layered architecture (never skip a layer)

```
router (app/api/routes/)      HTTP only: validate via schema, call service, map errors → HTTP
  → service (app/services/)   business logic; raises DOMAIN errors; no FastAPI imports
    → repository (app/repositories/)  data access only: queries, returns ORM objects or None
      → model (app/models/)   ORM models
schema (app/schemas/)         Pydantic v2 request/response models — the API contract
deps (app/api/deps.py)        dependency injection wiring
```

Rules of thumb:
- **Routers stay thin.** No queries, no business rules. Translate domain exceptions to `HTTPException`.
- **Services never import FastAPI.** They raise domain errors (e.g. `ItemNotFoundError`); the router
  decides the status code. This keeps services unit-testable without HTTP.
- **Repositories `flush`, never `commit`.** The session dependency owns the transaction — it commits
  on success and rolls back on error. Don't commit inside repositories or services.
- **Schemas are separate from models.** Never return an ORM object directly; build the response with
  `SchemaRead.model_validate(obj)` (schemas set `from_attributes=True`).

## Adding a new resource (the recipe)

To add `<thing>`:

1. **Model** — `app/models/<thing>.py`.
2. **Schemas** — `app/schemas/<thing>.py`: `<Thing>Base`, `<Thing>Create`, `<Thing>Read`
   (`model_config = ConfigDict(from_attributes=True)`).
3. **Repository** — `app/repositories/<thing>.py`: data access; `flush` + `refresh`, never `commit`.
4. **Service** — `app/services/<thing>.py`: business logic; define a `<Thing>NotFoundError`.
5. **Deps** — add `get_<thing>_service` + `<Thing>ServiceDep` in `app/api/deps.py`.
6. **Router** — `app/api/routes/<thing>.py`: thin CRUD; include it in `app/main.py`.
7. **Migration** — see `.claude/rules/database-*.md` for the database-specific migration recipe.
8. **Tests** — `tests/test_<thing>.py`: cover create, list, get-missing (404), validation (422),
   delete.

## Conventions

- **Type everything.** Public functions get full annotations and docstrings (args, returns, raises)
  per `.claude/rules/documentation.md`. mypy must pass on `app`.
- **API metadata.** Every route has a `summary` and an explicit `response_model` / `status_code`.
- **Settings via env.** Add config to `app/core/config.py` (`Settings`); never read `os.environ`
  scattered through the code. Document new env vars in `.env.example` and the README.
- **Errors:** raise domain exceptions in services; map to `HTTPException` in routers with a clear
  `detail`. Don't leak stack traces or ORM objects in error responses.
- **Migrations are reviewed, not trusted.** Always read an autogenerated migration before applying;
  autogenerate misses some changes (server defaults, enum/type changes, renames). See the database
  overlay rule for the exact tool and commands.

## HTTP status & error mapping

This is the concrete mapping the router applies when it translates domain results/errors to HTTP (per
the layered-architecture rule above — services raise domain errors, the router maps them; do **not**
scatter a second, conflicting mapping via global handlers).

**Method → success status:**

| Operation | Method | Success status |
|---|---|---|
| Create | `POST` | `201 Created` |
| Read / list | `GET` | `200 OK` |
| Full/partial update | `PUT` / `PATCH` | `200 OK` (return the updated resource) |
| Async accepted (job queued) | `POST` | `202 Accepted` |
| Delete | `DELETE` | `200 OK` with a small result body, or `204 No Content` |

**Domain error → status** (give each domain exception one status; map it in the router):

| Domain exception | Status |
|---|---|
| `<Thing>NotFoundError` | `404` |
| validation / bad input not caught by the schema | `422` |
| permission / ownership failure | `403` (or `404` to avoid leaking existence) |
| conflict / duplicate / state violation | `409` |

Catch the **specific** domain exception and map it — never a blanket `except Exception` that collapses
distinct failures into one generic `500`.

## Service-layer conventions

- **Logging discipline.** Use the stdlib logger with structured `extra={}`, not f-strings in the log
  call (`logger.info("created", extra={"thing_id": str(thing.id)})`, not
  `logger.info(f"created {thing.id}")`). Pass identifiers as `str(...)` in `extra`. Avoid the reserved
  `LogRecord` field names (`name`, `msg`, `args`, `levelname`, `module`, `process`, …) as `extra`
  keys — they raise at log time. On a caught error, log with `exc_info=True` so the traceback is kept.
- **Avoid N+1.** When you will touch a relationship for a set of rows, eager-load it
  (`selectinload(...)`) rather than lazy-loading per row in a loop.
- **Soft delete.** If the project soft-deletes, every default query filters `is_deleted == False`
  (or the project's flag); "get by id" must not silently return a soft-deleted row.
- **Name methods for the business operation**, not the CRUD verb: `approve_order(...)`, not
  `update_order_status(...)` — the intent belongs in the name.

## Naming on the wire

Keep field names **`snake_case` end to end** — model, schema, and JSON. Don't add `Field(alias=...)`
or `populate_by_name` to expose camelCase; a single casing convention across the stack removes a whole
class of "works in Python, wrong on the wire" bugs. (The frontend overlay consumes snake_case
directly — see `react-patterns.md`.)

## Reading live database state

When you need to inspect real data (debugging, verifying a migration, checking a fixture):

- Read it through the **tested service/repository layer or a project inspection command** — not a
  throwaway script that opens its own session against the live DB.
- In async code, **never block** the event loop: use the async session/driver; don't drop a synchronous
  DB call or `time.sleep` into an async path.

## Which tests to run for a change

Route by what changed (run the project's test command scoped to the relevant area; see `CLAUDE.md`
Commands):

| Changed | Run |
|---|---|
| a service | that service's unit tests |
| a router/endpoint | the API tests for that route |
| a schema | unit tests **and** the contract tests (the schema is the wire contract) |
| both layers / cross-cutting | the full backend suite |

## Contract fixtures (API contract tests)

Generate request/response fixtures **from the Pydantic schemas** (e.g. with a factory such as
polyfactory) rather than hand-writing JSON: schema-derived fixtures fail loudly when the schema
changes, which is exactly the drift you want a contract test to catch (see the `test-plan-review`
skill on the stale-fixture false-pass trap). Hand-written fixtures silently keep passing against the
old shape.

## Pre-removal search recipe

The concrete searches behind the **Pre-Removal Safety Check** in
`.claude/rules/deprecation-and-migration.md`. Before deleting a symbol, sweep every surface:

```bash
SYM=TheSymbolOrPath           # e.g. OrderResponse  or  /api/v1/orders/{id}

grep -rn "$SYM" app/                       # routers, services, repositories, deps
grep -rn "$SYM" app/workers/ app/tasks/    # background jobs / durable workflows (runtime refs)
grep -rn "$SYM" app/consumers/ app/events/ # message consumers/producers
grep -rn "$SYM" alembic/ migrations/       # migration history
grep -rn "patch(.*$SYM\|from .*import.*$SYM" tests/   # the most-missed: test mocks/patches by import path
```

A `unittest.mock.patch("app.services.order.OrderService")` target that no longer resolves **fails
silently** — the patch hits nothing and the test passes against a non-existent symbol. Search tests
explicitly, then remove one symbol at a time and run that area's tests.
